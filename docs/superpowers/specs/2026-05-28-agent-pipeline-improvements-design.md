# Agent Pipeline Improvements Design
Date: 2026-05-28

## Problem

Three classes of failures were observed while fixing `wanleung/cue-test` PR #3
(FastAPI/SQLAlchemy backend for a snooker community app):

1. **Field/enum naming inconsistencies** — tests used `content`, implementation used
   `body_text`; enum strings like `"new"` vs `"used_new"`, missing values like `"abusive"`.
   Root cause: QA agent and engineer agent independently invented names with no shared contract.

2. **Test infrastructure failures** — QA used `unittest.mock.patch()` for FastAPI `Depends()`
   instead of `app.dependency_overrides`, causing every test to return 422. Also missing
   fixtures (`mock_model`, `deletion_request_data`, etc.) that QA's own tests required.
   Root cause: Neither QA role prompt nor engineer role prompt contained FastAPI DI rules.

3. **Commit SHA conflicts** — the `revise` pipeline hit 409 errors when committing because
   cached SHA values were stale after multiple revision rounds. Pipeline aborted mid-revision.
   Root cause: `github_client.commit_file()` had no retry logic on 409 conflict.

## Scope

Affects `ai-software-house` pipeline only. No changes to `wanleung/cue-test` or any external repo.
Target LLMs: all (general robustness) + Mimo-specific hardening via examples in prompts.

---

## Architecture

The improved pipeline adds a **Naming Contract** artifact and **Contract Validator** stage:

```
PM → Architect → [naming_contract.yaml] → QA Planner → QA Engineer
     → [Contract Validator ← NEW] → Engineer → Reviewer
     → TDD Reviewer → Test Fix → Validation Gate → Deploy
```

Five deliverables:

| # | Deliverable | Type | Addresses |
|---|-------------|------|-----------|
| 1 | `naming_contract.yaml` schema + Architect rule | New artifact + role change | Naming inconsistency |
| 2 | `contract_validator` pipeline stage + agent role | New stage | Naming inconsistency |
| 3 | `roles/qa_engineer.md` — FastAPI DI rules added | Role change | Test infrastructure |
| 4 | `roles/engineer.md` — contract reference rule added | Role change | Naming inconsistency |
| 5 | `github_client.commit_file()` SHA retry on 409 | Bug fix | Commit conflicts |
| 6 | RAG test indexing after `qa_write` stage | Enhancement | Engineer naming lookups |

## Deliverable 1: Naming Contract

### File Location
`workspace/<project>/naming_contract.yaml` — generated by Architect alongside `architecture.md`.

### Schema

```yaml
version: 1
endpoints:
  - path: /api/forum/posts
    method: POST
    auth: required                              # required | optional | none
    request_fields: [title, content, image_urls, video_url]
    response_fields: [id, title, content, author_id, created_at]
  - path: /api/users/me/delete
    method: POST
    auth: required
    request_fields: [confirm]
    response_fields: [message]

enums:
  ItemCondition: [used_new, used_good, used_fair, new]
  ReportReason: [spam, abusive, inappropriate, harassment, other]
  UserStatus: [active, suspended, deleted]
  UserRole: [player, venue_owner, admin]

service_signatures:
  - fn: deletion_service.permanently_delete_user_data
    args: [user_id_str]       # string, NOT uuid object
  - fn: email_service.send_deletion_confirmation
    args: [email_str, user_id_str]
```

### Architect Prompt Rule (added to `roles/architect.md`)

```
## Naming Contract (Required Output)

After writing architecture.md, you MUST produce `naming_contract.yaml` in the workspace.
Rules:
- Every API endpoint must list exact request_fields and response_fields (the names that
  tests will use in json={...} payloads and response.json() assertions).
- Every enum type must list ALL valid string values.
- Any service function with a non-obvious signature must be listed under service_signatures.
- Field names must be consistent across all endpoints (no snake_case vs camelCase mixing).
- Enum values must be lowercase_with_underscores unless the PRD specifies otherwise.

This contract is the single source of truth. QA and Engineer agents will reference it.
```

## Deliverable 2: Contract Validator Stage

### New Role: `roles/contract_validator.md`

The Contract Validator reads `naming_contract.yaml` and all test files. It checks:

1. Every `json={...}` payload field in tests appears in the contract's `request_fields`
2. Every `response.json()` key assertion matches `response_fields`
3. Every enum string literal (e.g. `"abusive"`, `"used_new"`) appears in the contract's enum lists
4. Service call signatures in test mocks match `service_signatures`

Output: either `PASS` (all aligned) or a list of divergences with suggested fixes.

### Pipeline Integration (`orchestrator.py`)

- Add `stages["contract_validate"]` after `stages["qa_write"]`
- Stage fails (blocks pipeline) if validator returns divergences
- On failure: validator's output is appended to QA engineer's context for a re-run (same retry
  pattern as existing `test_fix` stage)
- Skip condition: `stage_skips.get("contract_validate")` — can be disabled per-project

### Stage Definition

```python
stages["contract_validate"] = PipelineStage(
    name="contract_validate",
    label="Contract Validation",
    checkpoint_key="contract_validate",
    fn=lambda r: self._stage_contract_validate(r),
)
```

## Deliverable 3: QA Engineer Prompt Hardening

Add to `roles/qa_engineer.md` (mirrors rules already in `tdd_reviewer.md`):

```markdown
## FastAPI Test Infrastructure (Critical Rules)

### 1. dependency_overrides — never use patch() for FastAPI Depends()

The ONLY correct way to override FastAPI dependencies in tests:

    from app.main import app          # import BEFORE any patching
    from app.dependencies import get_db

    async def override_get_db():
        yield mock_db                 # YIELD not return — get_db is async generator

    app.dependency_overrides[get_db] = override_get_db
    client = TestClient(app)
    yield client
    app.dependency_overrides.pop(get_db, None)

Using unittest.mock.patch() causes FastAPI to inspect MagicMock(*args, **kwargs) and
inject them as required query params → every test returns 422.

### 2. Mock user required fields

    sample_user_obj = {
        "id": uuid4(),
        "email": "test@example.com",
        "display_name": "Test User",
        "status": "active",        # NOT "user" — must be valid UserStatusEnum value
        "role": "player",          # NOT "user" — must be valid UserRoleEnum value
        "firebase_uid": "google-123456",
    }

### 3. All field names MUST match naming_contract.yaml

Read naming_contract.yaml before writing any test. Use the exact field names listed there
in all json={...} payloads and response.json() assertions.
```

## Deliverable 5: Commit SHA Retry

Add retry-on-409 to `github_client.py`:

```python
def commit_file(self, path, content, message, branch, sha=None, *, _retry=True):
    """Commit a file; auto-retries once on 409 SHA conflict."""
    try:
        return self._do_commit(path, content, message, branch, sha)
    except GitHubAPIError as e:
        if _retry and "409" in str(e):
            # SHA stale — fetch current SHA and retry once
            fresh = self._get_contents_sha(path, branch)
            return self.commit_file(path, content, message, branch,
                                    sha=fresh, _retry=False)
        raise

def _get_contents_sha(self, path, branch):
    """Fetch the current blob SHA for path on branch."""
    result = self._request("GET", f"/repos/{self.repo}/contents/{path}",
                           params={"ref": branch})
    return result.get("sha")
```

## Deliverable 6: RAG Test Indexing

After `_stage_qa_write()` saves test files to the workspace, index them:

```python
# in _stage_qa_write(), after writing files
if self.repo_auto_indexer and result.test_files:
    self.repo_auto_indexer.index_files(result.test_files)
    log.info("[qa_write] indexed %d test files into RAG", len(result.test_files))
```

This allows the Engineer to call:
```
search_docs("what field name does test_forum.py expect for post body?")
→ "content" (found in test_forum.py line 47: json={"title": ..., "content": ...})
```

## Error Handling

| Scenario | Handling |
|----------|----------|
| Architect doesn't produce naming_contract.yaml | Contract Validator stage warns and skips (non-blocking first time); blocking on 2nd+ revision |
| Contract Validator finds divergences | QA engineer re-runs with divergences appended to context; max 2 re-runs then human review |
| 409 commit conflict | Auto-retry once with fresh SHA; if second attempt also fails, raise and log for human |
| RAG index unavailable | Skip indexing, log warning; does not block pipeline |
