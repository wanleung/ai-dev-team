# RAG MCP Server — Design Spec

**Date:** 2026-04-20  
**Status:** Approved  

---

## Problem

Agents in the ai-software-house pipeline generate code, architecture, and tests from the requirement and prior-stage context alone. They have no access to:
- Existing codebase patterns and APIs
- Past pipeline runs (institutional memory)
- External documentation and architecture guides

This leads to hallucinated APIs, re-invented patterns, and designs that drift from established conventions. RAG (Retrieval-Augmented Generation) fixes this by letting agents search a knowledge base on demand before generating.

---

## Approach

A dedicated **RAG MCP Server** (FastAPI) exposes three retrieval tools over HTTP/MCP. Agents call these tools on-demand via the existing `call_with_tools()` infrastructure — no changes to `BaseAgent`. The vector store is pgvector on the existing Postgres instance. Embeddings are generated by a configurable backend (Ollama or vLLM) running on the local network.

---

## Architecture

```
                    ┌─────────────────────────────┐
                    │      ai-software-house       │
  Orchestrator ──▶  │  EngineerAgent               │
                    │  ArchitectAgent  ──tools──▶  │──▶ RAG MCP Server :8001
                    │  QAPlannerAgent              │         │
                    │  QAEngineerAgent             │    ┌────▼──────────────────┐
                    └─────────────────────────────┘    │  pgvector (Postgres)  │
                                                        │  rag_embeddings table │
                    ┌──────────────────┐               └───────────────────────┘
                    │  Indexer CLI     │──embed+store──▶       ▲
                    └──────────────────┘               Ollama / vLLM (network)
                           ▲
              codebase / MemoryStore / docs
```

**Key decisions:**
- MCP server is the integration point — no changes to `BaseAgent` or the tool-calling loop
- pgvector reuses the existing Postgres in `server/`; no new database service
- Embedding backend is config-driven (`EMBED_BACKEND=ollama|vllm|openai`)
- Ollama/vLLM are accessed over the local network via configurable `BASE_URL`
- If the RAG MCP server is not configured in `config.yaml`, all affected agents fall back to `call()` — fully backwards compatible

## Components

### 1. pgvector Schema

New migration applied to the existing Postgres:

```sql
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE rag_embeddings (
    id          BIGSERIAL PRIMARY KEY,
    source_type TEXT NOT NULL,   -- 'codebase' | 'memory' | 'docs'
    source_id   TEXT NOT NULL,   -- file path, run_id, or doc name
    chunk_index INT  NOT NULL,   -- position within source document
    content     TEXT NOT NULL,   -- raw text of the chunk
    embedding   vector(768),     -- nomic-embed-text / bge-m3 / text-embedding-3-small
    metadata    JSONB            -- e.g. {"language":"python","tags":["auth"],"ts":...}
);

-- HNSW index for fast approximate nearest-neighbour search
CREATE INDEX ON rag_embeddings USING hnsw (embedding vector_cosine_ops);

-- Unique constraint for idempotent upserts
CREATE UNIQUE INDEX ON rag_embeddings (source_type, source_id, chunk_index);
```

Embedding dimension is 768 (default for `nomic-embed-text` and `bge-m3`). If a different model with different dimensions is used, the column must be recreated. Document the model + dimension in `.env`.

---

### 2. Embedding Client (`server/rag-mcp/embedder.py`)

A single `Embedder` class with three backends, selected by `EMBED_BACKEND` env var:

| Backend | Env var | Endpoint | Request format |
|---|---|---|---|
| `ollama` | `OLLAMA_BASE_URL`, `OLLAMA_MODEL` | `POST /api/embeddings` | `{"model":"...","prompt":"..."}` |
| `vllm` | `VLLM_BASE_URL`, `VLLM_MODEL` | `POST /v1/embeddings` | `{"model":"...","input":"..."}` |
| `openai` | `OPENAI_API_KEY`, `OPENAI_EMBED_MODEL` | `POST /v1/embeddings` | OpenAI SDK |

All backends return `list[float]`. Caller does not need to know which backend is active.

```python
class Embedder:
    def embed(self, text: str) -> list[float]: ...
    def embed_batch(self, texts: list[str]) -> list[list[float]]: ...
```

**Error handling:** Network errors raise `EmbedderError` (wraps the underlying exception with context). The indexer catches this and logs a warning per chunk — indexing continues for remaining chunks.

---

### 3. Indexer CLI (`server/rag-mcp/indexer.py`)

Command-line script to populate `rag_embeddings`. Run manually or via cron.

```bash
# Index a code repository
python indexer.py --source codebase --path /path/to/repo [--ext py,ts,go]

# Index past pipeline runs from MemoryStore
python indexer.py --source memory --db /path/to/memory.db

# Index documentation files
python indexer.py --source docs --path /path/to/docs [--ext md,txt,rst]
```

**Chunking strategy:**
- Code files: 40-line chunks with 10-line overlap
- Markdown/text: 500-token chunks with 50-token overlap
- Each chunk stored with `source_type`, `source_id` (file path or run ID), `chunk_index`

**Idempotency:** Upserts by `(source_type, source_id, chunk_index)` — re-running is safe. Stale chunks (from deleted files) are not automatically removed; a `--clean` flag will delete embeddings whose `source_id` no longer exists on disk.

### 4. RAG MCP Server (`server/rag-mcp/main.py`)

FastAPI application exposing three MCP-compatible tools.

**Tools:**

```
search_codebase(query: str, top_k: int = 5) -> list[SearchResult]
  Searches source_type='codebase'. Returns ranked code chunks with file path and line range.

search_memory(query: str, top_k: int = 5) -> list[SearchResult]
  Searches source_type='memory'. Returns past PRD, design, and summary excerpts with run metadata.

search_docs(query: str, top_k: int = 5) -> list[SearchResult]
  Searches source_type='docs'. Returns documentation chunks with source file name.
```

**SearchResult schema:**
```python
class SearchResult(BaseModel):
    content: str         # the raw chunk text
    source_id: str       # file path or run_id
    chunk_index: int
    score: float         # cosine similarity (0–1)
    metadata: dict       # language, tags, timestamp, etc.
```

**Search implementation:**
1. Embed the query using the configured `Embedder`
2. Run pgvector cosine similarity search filtered by `source_type`
3. Return top-k results ordered by score descending

**MCP endpoint:** `POST /mcp` — standard MCP JSON-RPC over HTTP, compatible with the existing `MCPToolRegistry`.

**Health endpoint:** `GET /health` — returns `{"status":"ok","db":"ok","embedder":"ok"}`. Used by docker-compose healthcheck.

### 5. Agent Integration

**Orchestrator changes:**  
When `mcp.servers` in `config.yaml` contains a server named `rag`, the orchestrator passes RAG tools to the following agents via `call_with_tools()`:

| Agent | RAG tools available | Fallback if no RAG |
|---|---|---|
| `EngineerAgent` | `search_codebase`, `search_docs` | `call()` |
| `ArchitectAgent` | `search_memory`, `search_docs` | `call()` |
| `QAPlannerAgent` | `search_codebase` (+ existing tools) | existing tool call |
| `QAEngineerAgent` | `search_codebase` | `call()` |

`ProductManagerAgent`, `PMReviewerAgent`, `ArchitectReviewerAgent`, `CodeReviewerAgent`, `SummaryAgent`, and memory agents are NOT given RAG tools — their tasks do not benefit from retrieval.

**config.yaml addition:**
```yaml
mcp:
  servers:
    - name: rag
      type: http
      url: "http://localhost:8001/mcp"
```

### 6. docker-compose Integration

New service added to `server/docker-compose.yml`:

```yaml
rag-mcp:
  build: ./rag-mcp
  ports:
    - "8001:8001"
  depends_on:
    db:
      condition: service_healthy
  environment:
    DATABASE_URL: postgresql://user:pass@db:5432/dbname
    EMBED_BACKEND: ollama                          # ollama | vllm | openai
    OLLAMA_BASE_URL: http://192.168.1.x:11434      # network Ollama
    OLLAMA_MODEL: nomic-embed-text
    # VLLM_BASE_URL: http://192.168.1.x:8000       # uncomment to switch to vLLM
    # VLLM_MODEL: BAAI/bge-m3
  healthcheck:
    test: ["CMD", "curl", "-f", "http://localhost:8001/health"]
    interval: 10s
    retries: 5
```

## Error Handling

| Failure | Behaviour |
|---|---|
| Embedder unreachable (Ollama/vLLM down) | Indexer: logs warning, skips chunk. MCP tool: returns `{"error":"embedder unavailable","results":[]}` |
| pgvector / Postgres down | MCP tool: returns empty results with error message. Agent continues without RAG context. |
| Embedding dimension mismatch | Indexer raises `ValueError` with clear message at startup; stops indexing |
| MCP server unreachable | Orchestrator logs warning, falls back to `call()` for that agent |
| Query returns 0 results | Tool returns empty list — agent proceeds without RAG context |

## Testing

**Unit tests** (`tests/test_rag_*.py`):
- `test_embedder_ollama` — mock HTTP, verify request format and response parsing
- `test_embedder_vllm` — same for vLLM endpoint format
- `test_search_codebase` — mock pgvector, verify SQL query and result mapping
- `test_search_memory` — same for memory source type
- `test_search_docs` — same for docs source type
- `test_indexer_chunking` — verify chunk sizes and overlap for code and text
- `test_indexer_idempotent` — index same file twice, assert no duplicate rows

**Integration test** (`tests/integration/test_rag_integration.py`):
- Start with a clean `rag_embeddings` table
- Index a small fixture directory (3 Python files, 1 markdown)
- Run `search_codebase("database connection")` — assert top result is from the fixture
- Run `search_docs("installation")` — assert top result is from the markdown fixture

## Environment Variables

| Variable | Default | Description |
|---|---|---|
| `DATABASE_URL` | — | Postgres connection string (required) |
| `EMBED_BACKEND` | `ollama` | `ollama` \| `vllm` \| `openai` |
| `OLLAMA_BASE_URL` | `http://localhost:11434` | Ollama server URL (network-accessible) |
| `OLLAMA_MODEL` | `nomic-embed-text` | Ollama embedding model name |
| `VLLM_BASE_URL` | `http://localhost:8000` | vLLM server URL |
| `VLLM_MODEL` | `BAAI/bge-m3` | vLLM embedding model name |
| `OPENAI_API_KEY` | — | Required only when `EMBED_BACKEND=openai` |
| `OPENAI_EMBED_MODEL` | `text-embedding-3-small` | OpenAI embedding model |
| `RAG_TOP_K` | `5` | Default number of results per search |
| `CHUNK_SIZE_CODE` | `40` | Lines per code chunk |
| `CHUNK_OVERLAP_CODE` | `10` | Overlap lines for code chunks |
| `CHUNK_SIZE_TEXT` | `500` | Tokens per text/doc chunk |
| `CHUNK_OVERLAP_TEXT` | `50` | Overlap tokens for text chunks |
